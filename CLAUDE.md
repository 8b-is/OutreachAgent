# CLAUDE.md — 8b-is LinkedIn Outreach Agent (`linkedin-outreach-agent`)

## Mission

Generates citation-grounded, character-verified (`<= 300` char connection note + 3-touch DM sequence), anti-slop-audited LinkedIn outreach campaigns for 8b-is targeting Tier-1 open-weight AI labs (Sakana AI, Nous Research, Prime Intellect, Zyphra, Poolside AI) and Tokyo B2B 7-day Turnkey Sprint clients.

External callers should hit `linkedin-outreach-agent.run_outreach_campaign` first.

## Architecture at a glance

- **Pattern(s):** Dynamic Intake Routing + Conditional Escalation + Parallel Specialist Hunters + HUNT->PROVE Adversarial Audit (Depth 4)
- **Topology:** one AgentField node (`linkedin-outreach-agent`) with 8 reasoners and 2 deterministic `@app.skill()` functions
- **Entry reasoner:** `run_outreach_campaign` (`tags=["entry"]`) — orchestrates the full 4-layer pipeline
- **Deterministic skills (`@app.skill`):**
  - `lookup_prospect_and_proof_dossier` — resolves prospect profile (papers, repos, location) and canonical `8b-is` proof citations (`CIT-OMNI-ESP32`, `CIT-OMNI-ZYNQ`, `CIT-HEADROOMZ-MOE`, `CIT-HF-TRACES`, `CIT-ARNAUTH-PQ`, `CIT-8B-GRANTS`, `CIT-SPRINT-PKG-A/B/C`)
  - `list_tier1_lab_targets` — returns all 15 preloaded Tier-1 AI Lab & Tokyo B2B target profiles
- **Internal reasoners:**
  - `classify_outreach_track` (`.ai()`, Layer 2) — classifies the outreach track (`tokyo_in_person_hardware`, `verifiable_rl_environments`, `ssm_hardware_codesign`, `swe_agent_compression`, `b2b_turnkey_sprint`) and active citations
  - `deep_track_escalation` (`.ai()`, Layer 3) — conditional escalation invoked when `classify_outreach_track` is not confident
  - `extract_technical_bridge` (`.ai()`, Layer 3 parallel) — maps prospect papers/repos to canonical `8b-is` citations
  - `structure_commercial_or_collab_offer` (`.ai()`, Layer 3 parallel) — frames the in-person Tokyo hardware demo, RL environment collab, or 7-day Turnkey Sprint (`$6.5k` / `$9.5k` / `$12.5k`)
  - `draft_connection_note` (`.ai()`, Layer 3 parallel) — drafts the initial LinkedIn connection request note (`<= 300` characters)
  - `draft_multitouch_sequence` (`.ai()`, Layer 3 parallel) — drafts the Day 1 DM (`<= 450` chars), Day 3 technical artifact drop, and Day 7 closing CTA
  - `reconcile_campaign_sequence` (`.ai()` + orchestration, Layer 2) — coordinates adversarial audit and applies surgical revisions if needed
  - `challenge_outreach_draft` (`.ai()`, Layer 3) — runs deterministic anti-slop regexes + char-limit checks, invokes Layer 4 citation verification, and audits tone
  - `verify_citation_grounding` (`.ai()`, Layer 4) — verifies every metric and repository claim against the canonical `8b-is` proof registry
- **Inter-reasoner traffic:** all internal calls go through `app.call(f"{app.node_id}.X", ...)` or `router.call(f"{NODE_ID}.X", ...)`. Never direct HTTP.

## Why this architecture (not a chain)

LinkedIn outreach to frontier AI researchers fails immediately when generated by a single monolithic prompt: it either hallucinates metrics, violates LinkedIn's strict 300-character connection-note limit, or leaks recognizable AI clichés. By separating dynamic track routing (`classify_outreach_track` with conditional escalation to `deep_track_escalation`), parallel atomic drafting (`extract_technical_bridge`, `structure_commercial_or_collab_offer`, `draft_connection_note`, `draft_multitouch_sequence`), and a 2-stage HUNT->PROVE adversarial verifier (`challenge_outreach_draft` -> `verify_citation_grounding`), each model call operates on a narrow 3-4 field schema with deterministic fallbacks and hard character-limit gates.

## Primitive selection rules (binding)

- `.ai()` is used at bounded classification, drafting, and verification gates (`classify_outreach_track`, `deep_track_escalation`, `extract_technical_bridge`, `structure_commercial_or_collab_offer`, `draft_connection_note`, `draft_multitouch_sequence`, `challenge_outreach_draft`, `verify_citation_grounding`, `reconcile_campaign_sequence`). Every `.ai()` schema has 2-4 flat fields, includes `confident: bool`, and has a deterministic `fallback_*` constructor in `reasoners/helpers.py`.
- `@app.skill()` is used for deterministic prospect/citation lookup (`lookup_prospect_and_proof_dossier`, `list_tier1_lab_targets`).
- Plain Python helpers in `reasoners/helpers.py` handle prose rendering, deterministic character-limit trimming (`enforce_char_limit`), and banned-phrase regex scanning (`scan_anti_slop_violations`).

## Data-flow rules

- Structured JSON between code and reasoners (when code branches on `primary_track`, `passed_audit`, or `confident`).
- Natural-language prose strings (`render_dossier_to_prose`, `render_specialist_drafts_to_prose`, `render_registry_subset_to_prose`) between reasoners that feed each other LLM context.
- Every cross-boundary dict returned by `app.call` / `router.call` is explicitly reconstructed via `Model(**payload)`.

## Model selection

- Default model: `openrouter/google/gemini-2.5-flash` via `AI_MODEL` env.
- The entry reasoner `run_outreach_campaign` accepts an OPTIONAL `model: str | None = None` parameter in the request body and propagates it to all child reasoners via `app.call(..., model=model)`.
- Provider keys: `OPENROUTER_API_KEY` (default), `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY`.

## Runtime contract

- Local runtime is `docker-compose.yml` in this directory (or `af server` + `python main.py`).
- One container: `agentfield/control-plane:latest` (local mode, port `8080`).
- One container: `linkedin-outreach-agent`, built from `Dockerfile` (port `8001`, dashboard at `http://localhost:8001/dashboard`).

## Anti-patterns (reject these)

- ❌ Direct HTTP between reasoners. All internal traffic uses `app.call` / `router.call`.
- ❌ Passing `router.node_id` inside router files (does not exist; use `NODE_ID = os.getenv("AGENT_NODE_ID", "linkedin-outreach-agent")`).
- ❌ Passing raw JSON dicts into LLM `user=` prompts instead of rendered prose strings.
- ❌ Removing the `confident: bool` field from any `.ai()` schema or removing its `fallback_*` handler.
- ❌ Allowing any connection note to exceed 300 characters.

## Extension points (where to safely add work)

- Add new frontier lab or Tokyo B2B prospects: add an entry to `PROSPECT_DOSSIER_CATALOG` in `reasoners/helpers.py` and `CURATED_PRECISION_SEQUENCES` in `cli.py`.
- Add new `8b-is` proof citations (e.g. new silicon telemetry or grant milestones): add an entry to `PROOF_CITATION_REGISTRY` in `reasoners/helpers.py`.
- Add a LinkedIn API / HeyReach / Phantombuster webhook dispatcher: register a new `@app.skill()` in `main.py` that consumes `final_sequence` only when `governance_status == "APPROVED_READY_TO_SEND"`.
